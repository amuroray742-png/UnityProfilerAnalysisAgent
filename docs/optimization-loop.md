# 工具内优化项目

流程：导入 A → 诊断 → Unity 工程定位 → 确认任务与修改 Agent → 新会话修改 → 检查 → 手动录制 B → 对比 → 接受或回退。

## 使用

1. 正常完成首轮诊断和工程定位。新定位报告会附带结构化候选任务；没有实际读取的代码依据时只能调查。旧报告可以继续导出，但需要重新定位才能生成任务。
2. 打开“优化项目 · 修改与 A/B 复验”，选择已定位的 Unity 工程，在工程外选择一个保存目录。点击“将当前定位保存为一轮”。记录存放在 `optimization.json`，关闭或重启后用“打开优化项目”恢复。
3. 勾选优化或 Marker 任务，检查文件列表、证据、目标、禁止改变的行为和验收要求。只允许现有 Assets / 内嵌 Packages 中的 `.cs`、`.shader`、`.hlsl`、`.cginc`、`.compute`；不能创建、删除、改名或修改资源、meta、设置、包依赖。
4. 独立选择修改 Agent。默认沿用定位 Agent；切换不会改变已有报告。点击“确认本轮范围，开始修改”。**同 Agent 也新建 ACP 会话**；取消重试也是新会话，不恢复聊天历史。任务版本、实际 ACP 会话 ID 和修改记录单独保存。
5. 一组修改后检查 C# 编译、选定 Shader 和用户填写的 EditMode 测试（每行一个完整测试名称）。最多 3 次检查；没有选测试时会说明未运行测试。取消后可单独重新检查（仍计入本次运行的 3 次上限）。HLSL/CGINC/Compute 依赖 Shader 与全部变体检查不完整，明确显示无法完成。旧插件或 Editor 不可用时允许保留代码修改，但检查为不可用，不能算通过。不会自动安装插件、打开场景、运行 PlayMode 或构建。
6. 查看修改记录、检查结果。取消只停止后续工作，保留已写入文件。按同一设备、场景、操作、画质、分辨率、构建类型和 Profiler 设置重录 B；游戏操作和录制由用户完成。
7. 导入 B，填写两份录制的条件和版本，选择整段或各自连续原始帧区间，填写 P95 预算，比较 `B − A`。零基线没有百分比；缺失显示“—”，估算排除，部分覆盖不作完整达标结论。帧号不硬对齐，长度不同不比较总量。未限定区间的部分导出或区间缺帧时，不能给出完整达标结论。
8. “在分析页打开 B”可检查新 Marker。纯 Marker 任务按新采样是否回答调查问题人工验收，不按性能改善验收。玩法正确性、任务验收、用户决策与检查结果分别保存。
9. 接受本轮或回退；明确选择下一轮基线。下一轮在分析页导入选定基线、重新诊断和定位后保存任务，不沿用旧修改会话。最终记录可导出 Markdown / HTML，包含各阶段 Agent、条件、任务版本、实际差异、检查、复验与回退状态。

## 编辑与回退边界

- 用户未提交改动也作为原始字节备份；不要求 Git，不自动提交或清理。
- 编辑绑定优化项目、轮次、运行、选定任务与文件，逐次核对指纹。备份和终态立即落盘；流式正文最多 250 ms 合并一次，崩溃可能丢失未刷盘尾部文字。首次写入前保存 before/after 字节和 SHA-256，使用同目录临时文件替换。
- 保留 UTF-8/BOM、带 BOM UTF-16 与常见换行；单代码文件最多 2 MiB。禁止链接/junction 和路径越界。
- 多文件操作不是整体事务。中断记录区分已应用、待确认、未应用；打开项目时核对未决文件。回退按逆序恢复，外部修改或后续轮次依赖会阻止覆盖。
- 保存文件最多 128 MiB，超过上限报错，不静默删记录。保存目录和 Unity 工程都有跨进程租约；同一工程不能同时打开两个优化项目执行修改。备份不复制完整工程或录制。
- 检查通过固定插件命令执行，状态跨域重载写入 Library。检查前后核对业务文件清单：代码用 SHA-256，其他资产用大小与修改时间；发现变化暂停推进。此监测不能证明所有业务文件内容都未变化，最终应核对项目差异和玩法。
- Agent 位于临时目录，只开放当前性能查询与 `optimization_context/read/replace/check`。Claude 修改会话关闭内置工具；Codex 修改会话使用需用户授权模式、禁用 shell/web search；客户端只授权本会话白名单 MCP 请求。**这是适配器与工具范围限制，不是本工具实现的操作系统沙箱。**其他适配器未验证前不开放修改。

## 证据与比较

任务来自定位阶段实际读取的代码路径和指纹。选定任务、限制、既有修改和基线检查由后端分页面提供；默认只列报告索引，完整报告和资源证据以 report_id 按需读取，不复制整段对话；新会话仍可能耗尽模型上下文，此时保存状态后重试。

CPU、帧时间、GC 与可用渲染计数分别统计 mean/P50/P95/P99/max 和覆盖率。热点只按线程角色及完整 Marker 名路径关联，Job.Worker 同角色汇总不代表单个 Worker 对齐；不使用跨录制线程/Marker/Flow/对象 ID。新 Marker、改名或消失路径没有自动补零的对应值。inclusive 父子耗时不能相加，单次差异不证明优化因果或统计显著性。

导出不默认附带完整源码、通信日志、工程或录制。差异每次预览最多 200 行，超过时明确说明；完整原始字节和逐次变化保存在优化项目，完整修改详情可分页读取。HTML 沿用原有安全 Markdown 渲染及打印样式。

## 验证入口

- `cargo test --manifest-path src-tauri/Cargo.toml --locked --offline`
- `npm test`、`npm run build`
- `cargo test --manifest-path src-tauri/Cargo.toml --test optimization real_ -- --ignored --nocapture --test-threads=1`：真实 Codex / Claude，公开临时文件，只验证修改工具与回退，不代表实际游戏收益。
- `src-tauri/tests/optimization.rs`：持久化、编码、取消、指纹冲突、多轮回退、权限隔离和真实 ACP/MCP 文件变更。
- `unity/Packages/com.upaa.inspector/Editor/OptimizationChecks.cs`：固定检查协议；旧只读插件兼容降级。
- `src-tauri/tests/fixtures/unity-project/Assets/Tests/Editor`：公开 EditMode 行为测试及显式失败样例。失败样例标记 Explicit，不能作为普通测试通过的预期。

完整验收范围及未验证项见[项目状态](project-status.md)。
