# 工具内优化项目

流程：导入 A → 诊断 → Unity 工程定位 → 确认任务与修改 Agent → 新会话修改 → 检查 → 手动录制 B → 对比 → 接受或回退。

## 使用（非程序员）

1. 导入修改前的录制，完成性能诊断和 Unity 工程定位。
2. 在“优化项目”里选择修改 AI，点击 **开始优化**。补充要求可以留空，也可以写“保持玩法不变，优先减少卡顿”。无需勾选任务、指定代码文件或创建保存目录。
3. 等待 AI 调查、优化和检查。定位报告里的“继续调查”会成为 AI 的后续工作；找不到可靠原因时可以补采样，也可能只说明未解决的问题，不保证每项都能自动修好。
4. 查看“本轮结果”。“代码已修改”不代表性能已经变好；没有 Editor 或检查失败时，按提示处理。“查看详细记录”可展开文件、任务、会话与检查结果。
5. 在游戏里复测玩法，按相同设备、场景、操作和画质重新录制。在“下一步：导入新录制，比较效果”里导入 B，核对条件并对比。新 Marker 需要在新录制中核对。
6. 可以导出 Markdown / HTML，或点击 **撤销本轮代码修改**。已有外部修改或新引用时会停止回退，并明确指出冲突。

记录自动保存在应用数据目录的 `optimization-projects/<工程路径哈希>`，不是 Unity 工程内。展开“打开或管理优化记录”可查看位置；重启后用“打开优化项目”选择该目录。当前定位再次开始优化时自动复用匹配记录。同一轮重试、切换 AI 都新建会话。保存记录不复制完整工程和录制，请保留原始录制文件。

### 可选细节

- 修改 AI 默认沿用定位 AI，也可独立选择。当前验证范围为 Claude Code 与 Codex 的 ACP 适配器，不自动切换不可用 Agent。
- “检查选项”可填 EditMode 测试全名；留空仅做编译及可取得的 Shader 检查。不自动运行 PlayMode 或构建。
- A/B 默认不对齐同名帧号；可分别选择连续帧范围。差值为 B − A，缺失不填零、零基线无百分比，部分覆盖不宣称完整达标。
- 保留本轮、回退、下一轮基线、玩法确认均独立于编译结果。合成录制只用于测试流程，不是实际优化收益。

## 编辑与回退边界

- 用户未提交改动也作为原始字节备份；不要求 Git，不自动提交或清理。
- 自动优化绑定工程、轮次、新会话与内部任务；允许继续调查和扩展相关代码文件。旧受限接口仍绑定原先批准文件。每次修改都先读取当前指纹。备份和终态立即落盘；流式正文最多 250 ms 合并一次，崩溃可能丢失未刷盘尾部文字。首次写入前保存 before/after 字节和 SHA-256，使用同目录临时文件替换。
- 可修改 Assets／内嵌 Packages 的 C#、Shader、HLSL、CGINC、Compute；可在 Assets 新建同类代码及必要目录。禁止删除、重命名已有文件，禁止资源、设置、asmdef、依赖修改。新增文件以 UTF-8 保存，后端管理 meta；修改已有文件保留编码和换行，单文件 2 MiB。禁止链接/junction 和路径越界。
- 多文件操作不是整体事务。中断记录区分已应用、待确认、未应用；打开项目时核对未决文件。回退按逆序恢复，外部修改或后续轮次依赖会阻止覆盖。
- 保存文件最多 128 MiB，超过上限报错，不静默删记录。保存目录和 Unity 工程都有跨进程租约；同一工程不能同时打开两个优化项目执行修改。备份不复制完整工程或录制。
- 检查通过固定插件命令执行，状态跨域重载写入 Library。检查前后核对业务文件清单：代码用 SHA-256，其他资产用大小与修改时间；发现变化暂停推进。此监测不能证明所有业务文件内容都未变化，最终应核对项目差异和玩法。
- Agent 位于临时目录，自动模式开放当前性能、工程只读查询和 `optimization_context/read/replace/task/create/check`。Claude 修改会话关闭内置工具；Codex 修改会话使用需用户授权模式、禁用 shell/web search；客户端只授权本会话白名单 MCP 请求。**这是适配器与工具范围限制，不是本工具实现的操作系统沙箱。**其他适配器未验证前不开放修改。

- 新增文件有独立创建记录，回退核对文件内容、meta 和引用；目录只在为空时移除。无法完整检查引用时不自动删除新文件。旧记录版本 1 先备份为 `optimization.v1.backup.json` 再升级版本 2。

## 证据与比较

任务由新会话结合诊断、定位报告和实际工程继续调查后记录。任务、限制、既有修改和基线检查由后端分页面提供；默认只列报告索引，完整报告和资源证据以 report_id 按需读取，不复制整段对话；新会话仍可能耗尽模型上下文，此时保存状态后重试。

CPU、帧时间、GC 与可用渲染计数分别统计 mean/P50/P95/P99/max 和覆盖率。热点只按线程角色及完整 Marker 名路径关联，Job.Worker 同角色汇总不代表单个 Worker 对齐；不使用跨录制线程/Marker/Flow/对象 ID。新 Marker、改名或消失路径没有自动补零的对应值。inclusive 父子耗时不能相加，单次差异不证明优化因果或统计显著性。

导出不默认附带完整源码、通信日志、工程或录制。差异每次预览最多 200 行，超过时明确说明；完整原始字节和逐次变化保存在优化项目，完整修改详情可分页读取。HTML 沿用原有安全 Markdown 渲染及打印样式。

## 验证入口

- `cargo test --manifest-path src-tauri/Cargo.toml --locked --offline`
- `npm test`、`npm run build`
- `cargo test --manifest-path src-tauri/Cargo.toml --test optimization real_ -- --ignored --skip real_automatic --nocapture --test-threads=1`：真实 Codex / Claude，公开临时文件，只验证修改工具与回退，不代表实际游戏收益。
- 自动新增/编译/回退验收使用 `real_automatic` 测试过滤器，并显式设置 `UPAA_PUBLIC_UNITY_PROJECT` 为已打开、带 `.upaa-public-fixture` 的公开隔离工程；缺环境或文件会失败，具体步骤见[验收记录](evidence/automatic-optimization-validation.md)。
- `src-tauri/tests/optimization.rs`：持久化、编码、取消、指纹冲突、多轮回退、权限隔离和真实 ACP/MCP 文件变更。
- `unity/Packages/com.upaa.inspector/Editor/OptimizationChecks.cs`：固定检查协议；旧只读插件兼容降级。
- `src-tauri/tests/fixtures/unity-project/Assets/Tests/Editor`：公开 EditMode 行为测试及显式失败样例。失败样例标记 Explicit，不能作为普通测试通过的预期。

完整验收范围及未验证项见[项目状态](project-status.md)。
