# 工具内优化项目

第一次使用、只想知道每一步点哪里，请先看[非程序员简单使用说明](quick-start.md)。本文保留完整操作、技术边界和验证入口。

## 使用（非程序员）

1. 打开工具，点击 **新建优化项目**，选择 Unity 工程目录；以后从首页的最近项目或 **打开优化项目** 接着做。
2. 点击 **导入录制 A**，选择优化前的 Profiler 文件。
3. 选择分析 AI，点击 **一键诊断并定位**。工具会先分析热点，再到工程里寻找原因；这一步不改代码。
4. 定位完成后选择修改 AI，点击 **开始优化**。补充要求可以留空；不需要勾选任务或填写代码路径。
5. 查看改了什么、编译检查是否通过。自己运行游戏确认玩法，再按相同场景和操作录制 B。
6. 点击 **导入复测录制 B**，然后 **对比 A 与 B**。缺失数据或条件不同会提示，不能据此断言优化成功。
7. 选择 **接受本轮修改** 或 **回退本轮修改**。点击 **开始下一轮**：接受时默认将本轮 B 作为下一轮 A，回退时默认沿用原 A。诊断区域显示当前 A 的文件名、帧数和沿用来源；可以直接诊断，也可以先点击 **重新导入 A** 选择新的 Profiler 数据。

第一轮导入后同样可以 **重新导入 A**。替换只影响当前轮次，旧轮次的录制和报告仍保留；取消选择、解析失败、取消导入或保存失败不会替换已有 A。成功替换并保存后，再点击 **一键诊断并定位** 才会启动 AI。已有分析报告或修改记录后不能替换 A；重开项目会恢复最后成功保存的选择。

项目顶部的 **当前工作／历史轮次** 可以随时切换。进入历史轮次，选择要看的那一轮，再查看 **本轮概览、性能诊断、工程定位、代码修改、检查与对比**；报告版本和修改运行都保留，代码修改页点击文件即可看具体差异。已回退的修改也能查看。长内容通过上一页／下一页读完。按轮次导出 Markdown 或 HTML。关闭程序后重新打开项目即可继续；工具不会自行启动 AI，也不会自行修改代码。运行中先点击“停止当前任务”，再返回项目首页。

记录默认保存在应用数据目录的 `optimization-projects/<项目 ID>`；新建时可在高级设置选择工程之外的目录。主页面显示自动保存状态，历史记录区显示具体存档位置。不要只复制 `optimization.json`，备份时应复制整个存档目录。保存记录不复制 Unity 工程和原始录制，请保留原文件。

### 团队共享的 Unity 插件

打开项目后，在“Unity 插件”区域点击“重新检查”。关闭目标工程的 Unity Editor，再点击“安装到工程”；旧磁盘引用显示“迁移到工程内”。安装插件不需要选文件或再次确认，之后重新打开 Unity 等待编译，再检查连接。其他业务依赖不变，Unity CLI 不会自动安装。

把 `Packages/com.upaa.inspector`（含 `.meta`）、变更后的 manifest 和 Unity 更新的 lock 文件提交到工程仓库，其他成员无需使用相同个人目录。文件复制成功不等于编译成功；未连接仍可离线分析。不同版本／本地修改会提示冲突，不自动覆盖；中断后可继续安装。完整边界见[插件说明](../unity/Packages/com.upaa.inspector/README.md)。

### 工作时会看到什么

- 导入 A／B 会显示校验、解析、汇总和保存进度。字节总量明确时才显示百分比；JSON 等无法计算准确比例的阶段显示活动条。保存成功才显示导入完成，失败不会替换已有录制。
- AI 工作面板自动展示公开说明和操作摘要，例如查询热点、读取代码、修改代码和检查编译。文字随真实输出出现；没有公开输出时显示等待状态，不代表程序卡住，也不展示或模拟模型内部思考。
- 展开一条操作可看工具详情。向上翻阅后不会强制滚到最底部，点击“回到最新”恢复跟随。诊断、定位和优化用独立会话，工作阶段选择器可以回看。
- 历史轮次里的“查看此会话工作过程”可以重放已保存内容。旧版本没有保存该过程时会明确提示，原报告、代码差异和回退记录不受影响。
- 活动摘要每次会话最多保存 10 MiB；达到上限会明确说明。正式报告仍有独立的 2 MiB 上限和不完整状态，实际修改及恢复备份不受活动上限影响。工具返回全文和内部通信日志不默认存入活动摘要或导出报告。

### 中断后怎么办

- 诊断已完成、定位失败：点“继续诊断定位”，只重新进行定位。
- 修改被停止：已写入的代码不会自动撤销，可以查看、检查、在新会话继续，或回退。
- 录制移动了：高级选项里“重新定位录制文件”只接受指纹相同的原文件；报告仍能查看。
- 工程目录不可用：仍可打开存档，恢复原工程后才能继续定位、修改或回退。
- 回退提示冲突：说明代码被外部修改或有后续依赖，工具不会强行覆盖。
- 存档失败：停止推进并处理磁盘问题，不要把界面上的未保存内容当作已经存档。

### 可选细节

- 分析 AI 默认负责诊断和定位，高级设置可以为定位选另一个 AI；修改 AI 始终独立选择。每个阶段及重试均新建会话。
- “高级选项与详细指标”保留 CPU/GC、渲染、帧调用树与 Flow；调用树需要原始录制，已有汇总指标可从存档读取。
- EditMode 测试可留空；留空表示仅做编译及可取得的 Shader 检查。不自动运行 PlayMode 或构建。
- A/B 默认整段比较，也可分别设置帧区间、条件和预算。B − A 是观测差异，不代表确定因果。
- 纯 Marker 轮次检查新采样能否回答调查问题，不把补点当作性能改善。

## 编辑与回退边界

- 用户未提交改动也作为原始字节备份；不要求 Git，不自动提交或清理。
- 自动优化绑定工程、轮次、新会话与内部任务；允许继续调查和扩展相关代码文件。旧受限接口仍绑定原先批准文件。每次修改都先读取当前指纹。备份和终态立即落盘；正文先追加并同步日志，再对界面可见，重启重放已提交日志。首次写入前保存 before/after 字节和 SHA-256，使用同目录临时文件替换。
- 可修改 Assets／内嵌 Packages 的 C#、Shader、HLSL、CGINC、Compute；可在 Assets 新建同类代码及必要目录。禁止删除、重命名已有文件，禁止资源、设置、asmdef、依赖修改。新增文件以 UTF-8 保存，后端管理 meta；修改已有文件保留编码和换行，单文件 2 MiB。禁止链接/junction 和路径越界。
- 多文件操作不是整体事务。中断记录区分已应用、待确认、未应用；打开项目时核对未决文件。回退按逆序恢复，外部修改或后续轮次依赖会阻止覆盖。
- 版本 3 将索引、录制、轮次、报告及修改备份拆成指纹校验对象，单个对象读取上限 128 MiB；正文仍限制 2 MiB。旧版先备份完整 JSON 再迁移，失败不覆盖原索引。保存目录和 Unity 工程都有跨进程租约；同一工程不能同时打开两个优化项目执行修改。备份不复制完整工程或录制。
- 检查通过固定插件命令执行，状态跨域重载写入 Library。检查前后核对业务文件清单：代码用 SHA-256，其他资产用大小与修改时间；发现变化暂停推进。此监测不能证明所有业务文件内容都未变化，最终应核对项目差异和玩法。
- Agent 位于临时目录，自动模式开放当前性能、工程只读查询和 `optimization_context/read/replace/task/create/check`。Claude 修改会话关闭内置工具；Codex 修改会话使用需用户授权模式、禁用 shell/web search；客户端只授权本会话白名单 MCP 请求。**这是适配器与工具范围限制，不是本工具实现的操作系统沙箱。**其他适配器未验证前不开放修改。

- 新增文件有独立创建记录，回退核对文件内容、meta 和引用；目录只在为空时移除。无法完整检查引用时不自动删除新文件。旧记录版本 1／2 分别保留对应版本的完整备份，再迁移至版本 3。

## 证据与比较

任务由新会话结合诊断、定位报告和实际工程继续调查后记录。任务、限制、既有修改和基线检查由后端分页面提供；默认只列报告索引，完整报告和资源证据以 report_id 按需读取，不复制整段对话；新会话仍可能耗尽模型上下文，此时保存状态后重试。

CPU、帧时间、GC 与可用渲染计数分别统计 mean/P50/P95/P99/max 和覆盖率。热点只按线程角色及完整 Marker 名路径关联，Job.Worker 同角色汇总不代表单个 Worker 对齐；不使用跨录制线程/Marker/Flow/对象 ID。新 Marker、改名或消失路径没有自动补零的对应值。inclusive 父子耗时不能相加，单次差异不证明优化因果或统计显著性。

导出不默认附带完整源码、通信日志、工程或录制。本轮导出列出变更类型、文件、指纹和执行状态；完整原始字节和逐次变化保存在优化项目，完整修改正文及差异可分页读取。HTML 沿用原有安全 Markdown 渲染及打印样式。

## 安装包与开发验证

普通使用者直接安装已提供的安装包，无需运行开发命令。维护者构建安装包的命令、输出目录及验证边界见[发布说明](release-readiness.md#构建与分发)；`--no-bundle` 只生成程序，不生成安装包。

### 验证入口

- `cargo test --manifest-path src-tauri/Cargo.toml --locked --offline`
- `npm test`、`npm run build`
- `cargo test --manifest-path src-tauri/Cargo.toml --test optimization real_ -- --ignored --skip real_automatic --nocapture --test-threads=1`：真实 Codex / Claude，公开临时文件，只验证修改工具与回退，不代表实际游戏收益。
- 自动新增/编译/回退验收使用 `real_automatic` 测试过滤器，并显式设置 `UPAA_PUBLIC_UNITY_PROJECT` 为已打开、带 `.upaa-public-fixture` 的公开隔离工程；缺环境或文件会失败，具体步骤见[验收记录](evidence/automatic-optimization-validation.md)。
- `src-tauri/tests/optimization.rs`：持久化、编码、取消、指纹冲突、多轮回退、权限隔离和真实 ACP/MCP 文件变更。
- `unity/Packages/com.upaa.inspector/Editor/OptimizationChecks.cs`：固定检查协议；旧只读插件兼容降级。
- `src-tauri/tests/fixtures/unity-project/Assets/Tests/Editor`：公开 EditMode 行为测试及显式失败样例。失败样例标记 Explicit，不能作为普通测试通过的预期。

完整验收范围及未验证项见[项目状态](project-status.md)。
