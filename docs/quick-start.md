# 简单使用说明：找出卡顿，修改，再验证

适合策划、测试和其他非程序员。你负责操作游戏、录制和确认玩法；工具负责分析问题、让 AI 修改代码并保存记录。

**记住这一条流程：录制优化前的数据 → 分析 → 开始优化 → 再录一次 → 对比 → 保留或回退。**

## 开始前准备

- 游戏的 Unity 工程文件夹：里面应能看到 `Assets`、`Packages`、`ProjectSettings`。不是游戏安装目录。
- 一份 Unity Profiler 录制文件，通常以 `.data` 结尾。
- 工具中至少有一个可用的 AI。首次安装、登录和 Unity 连接环境，可以请负责环境的同事协助配置。

## 1. 新建或打开项目

第一次使用：点击 **新建优化项目**，选择游戏工程文件夹，再点击 **创建并进入**。项目名称可以保持默认。

以前用过：从首页的 **最近项目** 或 **打开优化项目** 进入，接着上次的步骤做，不需要重新建立项目。

### 第一次连接 Unity

在 **Unity 插件** 区域点击 **重新检查**。

- 提示未安装：先关闭这个工程的 Unity 窗口，再点 **安装到工程**。
- 显示 **迁移到工程内**：同样先关闭 Unity，再点击迁移。
- 安装完成后：重新打开 Unity，等待加载和编译结束，再点 **重新检查**。

**“插件文件已安装”不等于“Editor 已连接”**。Editor 就是 Unity 编辑器；连接成功后，工具能获取更多工程信息，也能进行代码检查。没连接时仍可分析，但部分信息或检查会缺失。

团队协作时，请让负责提交工程的同事一起提交新插件目录和相关包配置，其他人就不用设置相同的个人目录。遇到“内容冲突”时交给同事核对，不要自行删除旧插件。

## 2. 导入优化前的录制 A

先在游戏中复现要解决的问题，例如“进入关卡时卡一下”，用 Unity Profiler 保存这一段录制。

回到工具，点击 **导入录制 A**，选择文件，等待显示导入完成。解析过程中会显示进度；没有百分比的活动条也表示正在处理。

**A 就是优化前的数据。** 建议记下录制时的场景、操作和画质，之后照着再测一次。

## 3. 一键分析问题

选择一个可用的 **分析 AI**，点击 **一键诊断并定位**。

工具会先找出耗时、分配等问题，再到游戏工程里寻找可能的原因。工作面板会显示 AI 的公开说明和正在进行的操作。

**这一步只分析，不修改代码。** 等待诊断和定位都完成，再进入下一步。

## 4. 让 AI 开始优化

选择 **修改 AI**，点击 **开始优化**。它可以与分析 AI 相同，也可以不同。

“补充要求”可以留空，也可以写一句话，例如：

> 优先减少进入关卡时的卡顿，保持玩法和画面效果不变。

**从点击“开始优化”起，AI 才会实际修改工程代码。** 工具会保存修改记录，供之后查看或回退。

完成后主要看两件事：**改了什么、检查是否通过**。如果显示“检查失败”或“尚未编译验证”，先处理提示，不要直接当作优化成功。

## 5. 自己运行游戏，再录制 B

运行游戏，先确认操作、画面和玩法是否正常。再用尽量相同的设备、场景、操作和画质录制一次，保存为新文件，不覆盖 A。

点击 **导入复测录制 B**，再点击 **对比 A 与 B**。

**B 就是修改后的数据。** 代码检查通过，并不代表游戏一定更流畅；这一步需要你实际复测。

## 6. 保留还是回退

查看对比结果，并填写 **玩法是否正常**。

- 确认效果符合预期，玩法也正常：点击 **接受本轮修改**。
- 效果不理想，或者玩法出现问题：点击 **回退本轮修改**，等待回退成功。
- 提示数据不足或条件不同：先核对两次录制的方法，不急着判断优化成功。

如果 AI 只是增加了“采样点／Marker”，相当于加了更细的计时标签，目的是让下次分析更准确，**不代表已经变快**。

本轮结束后，点击 **开始下一轮**。接受修改后，上一轮 B 默认成为本轮 A；回退后默认沿用原 A。诊断按钮上方会显示 A 的文件名、帧数和沿用来源。

可以直接点击 **一键诊断并定位**，也可以先点击旁边的 **重新导入 A**，选择一份新的 Profiler 数据。第一轮同样可以换文件。只要本轮未结束、没有开始过优化且任务已停止，诊断或定位完成、失败、取消或中断后都可以换 A；定位完成后的页面也有这个入口。

成功换 A 会放弃本轮旧诊断、定位报告和相关任务，不再展示旧报告，轮次编号不变；需要手动点击 **一键诊断并定位** 重新诊断。此前轮次的记录仍保留。取消选择或导入、保存失败会保留原 A 和旧报告；成功后自动保存，重开项目仍使用新 A。已有优化运行记录后不能再换 A，即使那次优化失败或停止、没有修改文件。

## 之前的报告在哪里？

点击 **历史轮次**，选择要看的那一轮，可以查看诊断报告、工程定位、修改内容、检查和对比结果。回退过的修改也会保留记录。

需要发给同事时，在该轮导出报告。**HTML** 适合直接用浏览器阅读、打印；**Markdown** 适合交给程序或其他 AI 阅读。

记录会自动保存在本机，重开项目可以继续。请同时保留游戏工程和原始录制文件；工具的存档不会替你复制它们。

## 遇到问题怎么办？

| 看到的情况 | 怎么处理 |
|---|---|
| AI 显示不可用 | 请负责环境的同事检查 AI 安装、登录和配置 |
| AI 暂时没有文字输出 | 先看工作面板里的操作记录；没有文字不一定是卡住 |
| 诊断完成，但定位失败 | 点击 **继续诊断定位**，不必重做已经完成的诊断 |
| 想停止 AI | 点击 **停止当前任务**；已经写入的修改不会自动撤销，需要时另点回退 |
| 回退提示冲突 | 可能有其他人改过代码，请同事核对，不要强行覆盖 |
| 提示保存失败 | 先解决磁盘空间或访问问题，不能把当前内容当作已经保存 |

更多操作细节见[完整使用说明](optimization-loop.md)。
