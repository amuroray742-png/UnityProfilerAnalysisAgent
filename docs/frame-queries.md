# 原始帧与调用树查询

适用输入：Editor dump，以及已接通结构解码的 Unity 6000.3.23f1 `.data`。其他输入保留聚合指标，查询调用树会明确返回不可用。MCP stdio 服务复用本接口并已通过进程测试，并已注入桌面 ACP 会话，随诊断终态释放。

## 桌面使用

导入后进入 CPU 页，在“单帧调用树”选择原始帧号、线程和显示深度。线程列表超过 128 项时使用“更多线程”；样本使用上一页/下一页。默认线程要求唯一的 `Main Thread`，否则需明确选择线程。

表中的样本索引、父样本索引和深度来自原始树，不聚合成全局热点。每个样本耗时为 inclusive，不能把父子耗时相加当作总 CPU。GC 列使用字节，非分配样本与无效 GC 显示“—”；零字节分配仍显示 `0 B`。缩进最多显示 16 层，实际深度单独标明。

## 接口契约

Tauri 新增命令（原有命令名称和参数保持不变）：

| 命令 | 参数 | 返回与限制 |
|---|---|---|
| `frame_details` | fileId、frameIndex、start、limit | 帧信息与线程分页；start 是线程数组偏移；limit 为 1–128 |
| `cpu_hierarchy` | fileId、frameIndex、threadIndex（可空）、start、limit、maxDepth | 原始前序样本；start 是原始样本索引；limit 为 1–500；maxDepth 为 1–64 |
| `release_file` | fileId | 移除路径登记、快照与查询源；调用幂等 |

`frameIndex` 保留 dump 的原始帧号，允许部分导出的不连续帧号；二进制为录制中的序号，另保留头部 `rawFrameId`、`rawDuplicateId`。线程 ID 与原始纳秒时间戳使用十进制字符串，避免 JavaScript 超过安全整数范围。dump 未提供的原始二进制字段为 null。

`nextStart` 是下一页的起点，null 表示结束。深度从零开始，只返回 `depth < maxDepth` 的节点。`depthTruncated` 表示线程内存在被深度筛选排除的节点；父节点可能位于上一页，父索引保持原值。越界、缺失帧/线程、非唯一默认主线程和无查询源均返回错误。

## 存储与生命周期

- `.data` 保留打开的原文件句柄、帧位置、长度、指纹和该帧之前的 marker 状态。marker 表使用共享的写时复制存储；查询目标帧时独立解码，不从文件开头重放。文件长度或目标帧指纹变化时要求重新导入；指纹是变化检测，不是安全认证。
- dump 解析校验后将各帧结构写入独立临时文件，建立帧索引。Windows 使用 delete-on-close；Unix 打开后解除目录项。最后一个引用关闭后自动清理，不作为持久化快照。临时文件写入失败会使导入失败。
- 单次查询最多读取 128 MiB 的帧数据，超出返回错误；这限制原始读取量，**不是解析后的内存上限**。响应按样本/线程分页，查询不会返回整份录制的调用树。
- 读取与解码运行在阻塞工作线程。UI 重置、替换输入或卸载时释放登记；迟到的上传会主动释放，迟到的解析不能重新写回已释放的 fileId。在途查询持有独立引用，结束后释放。
- dump 与结构化 data 的帧摘要按名称合并 CPU、按线程和归因名称合并 GC，保留次数、总量和最大值。摘要行数不能代替原始样本数；查询源仍保存完整树和逐样本 metadata。
- 当前 JSON 导入仍持有完整类型化输入，二进制聚合仍累积帧摘要。独立解析进程、桌面 IPC 及结果页已测量，见[性能记录](performance-and-release.md)；长期内存/并发预算及磁盘配额仍待验收。

## 验证

[公开回归](../src-tauri/tests/frame_queries.rs)覆盖不连续帧号、64 位线程 ID、嵌套父子关系、GC 缺失、分页/深度边界和存储释放。[结构解析测试](../src-tauri/tests/unity6_structured.rs)覆盖跨帧 marker 状态和源文件变化；其私有集成测试新增逐帧详情存储对照及分页入口断言。

前端组件测试覆盖切帧、分页、深度提示、字节零值、过期响应丢弃及不可用错误；hook 测试覆盖重置时迟到上传和解析。后续 release WebDriver 已覆盖帧/线程/深度/分页控件，原生文件选择返回值由测试替代；资源测量另外区分 WebDriver 句柄干扰。具体数据范围及命令结果维护在[状态台账](project-status.md)。
