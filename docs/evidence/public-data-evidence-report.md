3. 可执行建议

针对优先项，先找到**触发大分配的调用入口**，并在其所属的具体业务操作及相邻操作上增加细粒度 marker。`Update` 的 **27 ms Self** 已通过区间校验，但仍包含等待和未细分工作，不能直接认定为计算时间；`Work` 的 1 ms 也不足以解释该尖峰。

- **修改建议 →** 若确认大分配来自可复用的临时缓冲或容器，改为保留容量、重置逻辑内容，避免同一事件反复重新创建。  
  **适用条件/代价 →** 数据生命周期允许复用；需要检查旧数据引用、线程访问和长期保留容量带来的内存占用。若结果必须独立保留，不能直接复用。  
  **验证方法 →** 重复触发同一操作，对比该分配路径的字节、次数及其所属业务 marker 的耗时，同时检查结果一致性。

- **修改建议 →** 若细分 marker 证实耗时来自一批可拆分处理，把该批次限制为每帧处理一定工作量。  
  **适用条件/代价 →** 操作允许跨帧完成且不要求原子性；会增加完成延迟，需要管理取消、状态一致性和处理中间画面。当前样本尚未证明存在这类批处理，不能直接套用。  
  **验证方法 →** 比较单帧最大耗时、整个操作总耗时、完成延迟及分配是否只是被转移到其他帧。

Worker 暂以补充 marker 为主：细分其 11 ms Self，并检查主线程是否存在对应依赖或等待。100 帧缺少匹配线程，无法提供可靠的同线程增量对照，暂不建议据此调整线程调度。
